# AGENTS.md

Guidance for coding agents working in this repository. See `README.adoc` for what the API is for and its compatibility
matrix.

Releases and `CHANGELOG.md` are generated by semantic-release from commit messages: do not edit the version or the
changelog by hand.

## Project

`gravitee-resource-ai-model-api` is the contract between the policies that use an AI model and the resource plugins
that supply one. It holds no model: each resource plugin (`gravitee-resource-ai-model-text-classification`,
`-token-classification`, `-text-embedding`, `-decision`) implements one of its abstract resources, and each policy
(`gravitee-policy-ai-prompt-guard-rails`, `-pii-filtering`, `-ai-semantic-caching`, the guardrails) calls it. The
gateway does not supply this API: every plugin bundles its own copy, so a change here only reaches a plugin when it
upgrades its dependency.

- `AiTextModelResource`: a model run by the gateway inference service (`gravitee-inference-api`). On start it loads
  the model through an `InferenceServiceClient` over the Vert.x event bus, waiting up to
  `inference.models.loadTimeout` (5 minutes by default), and unloads it on stop. Implementations give the client and
  turn its `MODEL_RESULT` into their `RESOURCE_RESULT` (`result`: `ClassifierResults`, `EmbeddingResult`)
- `decision`: `AiDecisionModelResource`, a model that answers keyed questions about a context with a decision and a
  confidence rather than with text. It has no lifecycle of its own: the implementation owns the client that reaches
  the model and releases it on stop
  - `Question` (sealed): `Noul` (yes or no, a name from the SystemOne specification: keep it), `Choice` or `Score`.
    Each is answered by the `Answer` subtype of the same name
  - `DecisionRequest`: the context, sent to the model as JSON, and the questions under their keys, in order
  - `DecisionResult`: the answers under the keys of the questions, the model, and the token usage when known
- `ModelInvokeException`: the model gave no usable answer. `ModelLifeCycleException`: it could not be loaded or
  unloaded

## Writing the API

- This is a published API used by several plugins: a change to a public type or signature breaks them when they
  upgrade. Mark such a commit as breaking (`feat!:` or a `BREAKING CHANGE:` footer) so semantic-release bumps the major.
- Value types are records, validated in their compact constructor: throw `IllegalArgumentException` for an invalid
  value (`NullPointerException` from `Objects.requireNonNull` for a missing required one), and copy collections into
  unmodifiable ones, keeping the order of maps with `LinkedHashMap`.
- Model a closed set of shapes with a sealed interface, so that consumers switch on it exhaustively without a
  `default` branch and a new shape breaks the build where it must be handled.
- Do not validate in the records what the model answers (probability bounds, a choice among those asked): the
  implementation checks the model output and fails with a `ModelInvokeException`, not an `IllegalArgumentException`.
- Javadoc every public type, record component and method: the plugins are written against it.
- Dependencies are `provided` (Vert.x, RxJava, resource API, Spring, Lombok, SLF4J): the gateway supplies them. Do not
  add a runtime dependency that every plugin would have to bundle without a strong reason.

## Build and test

- Java version from `.sdkmanrc` (`sdk env`). Lombok fails to compile on a newer JDK.
- `mvn clean install` builds and runs the tests.
- Validation (Prettier formatting, license headers) comes from `gravitee-parent`: format the code with Prettier
  (`mvn prettier:write`, `.prettierrc`, print width 140) and keep the Apache license header on new files.
- Tests use JUnit 5 with `@DisplayNameGeneration(ReplaceUnderscores)`, `should_...` method names, `@Nested` classes per
  concern, AssertJ, and `vertx-junit5` for the event bus.

## Commit conventions

- Conventional Commits format: `type: subject`, without a scope (the repository has one module).
- The subject must be lower-case.
- Header ≤ 72 characters.
- Each commit must build and pass its tests on its own.
- No `Co-Authored-By` trailer.
